Both call sites are covered. The fix: added `respinsRef` (mirroring the existing `spinTokenRef` pattern) as the authoritative, synchronously-updated counter that `spin()` checks and decrements, instead of relying on the `respins` React state value which only updates on the next render. This closes the race where two rapid clicks in the same event batch could both pass the `respins <= 0` guard and drive the count negative.
