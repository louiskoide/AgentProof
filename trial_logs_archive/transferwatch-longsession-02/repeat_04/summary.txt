I've added transfer chains to `TransferDesk.jsx`. The file compiles (checked with esbuild), but I haven't run it in a browser. The repo has no dev server or build setup, so I couldn't check the layout visually.

**How linking works:** chains are a new list, `SEED_CHAINS`, and the backend feed can send them too as a `chains` array. Each chain has an id, a title, a summary and an ordered list of steps. Each step points to an existing transfer by id. From the second step on, it can also say how it follows from the one before: `funds`, `replaces` or `triggers`, plus a short note. There's no way to create links inside the app, because the app has no editing screens; chains are set in the data like everything else. The comment describing the feed format now includes `chains`, and feed chains are merged with the seed ones by id, the same way transfers and stories are.

**How chains look:**
- Each chain gets a full-width panel above the three columns. It has a "Transfer chain" label, the title, the summary and a move count.
- The steps are the usual transfer cards laid out left to right, with a connector between each pair showing the link type and note. On narrow screens they stack vertically and the arrows point down.
- Each card in a chain shows its step number ("2/3") and its category (Interest, In Talks or Done), since it's no longer sitting in a column. So a chain can mix a done deal, a deal in talks and a rumour.
- **Chained transfers leave their columns** so they don't appear twice. This means the column counts no longer include them.
- **Filters:** a chain appears if any of its steps matches the league filter or search, and searching the chain's title or summary also works. Steps that don't match are faded rather than hidden, so the sequence stays intact.
- **Bad data:** steps pointing to unknown ids are skipped. A chain left with fewer than two steps isn't shown, and its transfer goes back to its column. If two chains list the same transfer, it only appears in the first one.

**Example chain, which you should check:** I added one chain built from transfers already in the data. Konaté → Real Madrid, then Upamecano → Liverpool as his replacement, then Bremer → Bayern.
